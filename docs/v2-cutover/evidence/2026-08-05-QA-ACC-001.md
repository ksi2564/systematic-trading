# QA-ACC-001 미인증 Access 경계 증적

## 판정

`PASS` — 외부에서 로그인하지 않은 사용자가 UI와 API에 접근하면 애플리케이션 본문을
직접 받지 않고 Cloudflare Access 로그인으로 이동한다.

| 요청·화면 | 실제 결과 | 기대 결과 | 판정 |

| `/api/v2/operations/status` | HTTP `302` → 같은 Access 로그인 경계 | API JSON 직접 노출 없음 | PASS |

리디렉션 URL의 query는 세션성 메타데이터를 포함하므로 저장하지 않고 제거했다. 쿠키,
토큰, 개인 이메일, OTP는 읽거나 기록하지 않았다.

쿼리와 `Set-Cookie`를 제외한 두 응답의 상태·Location, 정규화한 DOM 관찰값과 각각의
SHA-256은 [`2026-08-05-QA-ACC-001-sanitized.json`](2026-08-05-QA-ACC-001-sanitized.json)에
별도 저장했다. HTTP 경계는 2026-08-05T04:41:41+09:00에 같은 결과를 재확인했다.

## 증적 범위와 남은 항목

이 결과가 증명하는 범위는 **미인증 UI/API의 Access 차단**뿐이다.

- 허용 이메일 로그인과 동일 출처 UI/API 성공은 `QA-ACC-002`로 남아 있다.
- 비허용 이메일의 실제 거부 화면은 아직 검증하지 않았다.
- 브라우저 캡처 API가 Access 페이지에서 시간 초과되어 스크린샷은 통과 근거에
  포함하지 않았다. 대신 브라우저의 제목·헤딩·앱 문구 부재와 두 경로의 마스킹된
  응답 경계를 재현 가능한 정규형·해시 artifact로 함께 기록했다.
- 실제 주문, 계좌·전략·제어 변경, Java 중단, DNS·Access 정책 변경은 수행하지 않았다.

## 재현 원칙

새 미인증 브라우저에서 `https://app.wall-ant.com/`을 열고 다음만 확인한다.

1. 최종 화면 제목이 `Sign in ・ Cloudflare Access`인지 확인한다.
2. 헤딩이 `Log in to Wall-Ant v2`인지 확인한다.
3. `/api/v2/operations/status`가 인증 없이 JSON을 반환하지 않는지 확인한다.
4. 리디렉션 query, 쿠키, OTP는 증적에 저장하지 않는다.
