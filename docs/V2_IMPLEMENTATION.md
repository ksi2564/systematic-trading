# Wall-Ant v2 구현 기준

## 제품 흐름

1. 폼에서 전략 초안을 작성하고 불변 버전으로 저장한다.
2. 확보 가능한 데이터 범위를 표시한 백테스트를 실행한다.
3. 파라미터를 바꾸지 않은 채 여러 구간의 롤링 안정성을 확인한다.
4. 내부 모의투자에서 평가일, 신호, 주문 의도, 오류를 누적한다.
5. 사용자가 결과를 판단해 실전 후보를 명시적으로 승인한다.
6. 계좌에 저장된 위험 한도가 목표 포지션을 주문 의도로 변환하고 차단한다.

자동 최적화와 자동 승격은 없다.

각 수동 승격에도 서버가 완료 기록을 확인한다.

| 전환 대상 | 필수 완료 기록 |
| :--- | :--- |
| `BACKTESTED` | `BACKTEST` |
| `ROLLING_VALIDATED` | `ROLLING` |
| `PAPER` | 앞 단계의 수동 검토 |
| `LIVE_APPROVED` | 하루 이상 평가 후 완료한 `PAPER` 세션과 명시적 확인 |

같은 모의 세션의 동일 평가일·동일 입력은 성공과 실패 모두 저장을 반복하지 않고
같은 결과 또는 오류를 반환한다. 동일 평가일의 서로 다른 입력이나 과거 날짜 역순
입력은 거부한다. 위험 한도와 당일 사용량은 요청값이 아니라 서버의 계좌 기록만
사용한다. 서로 다른 모의 세션의 상태와 주문 의도는 세션 ID로 분리하되, 계좌별 당일
위험 사용량은 모든 세션이 공유한다.
규칙 기반 고정 종목군은 선택되지 않은 기존 종목을 0% 목표로 정규화해 전략 전환
시 보유 종목 청산이 누락되지 않게 한다.
전략 엔진별 파라미터는 초안 저장 전에 타입, 허용 범위, 알 수 없는 키를 검증한다.

## 현재 전략 기준선

- 신호: QQQM 종가와 ATH 대비 낙폭
- 낙폭 버킷: 15/25/35/45%
- 목표 비중: QQQM/QLD/TQQQ 순서로
  `100/0/0`, `60/30/10`, `40/40/20`, `30/30/40`, `20/20/60`
- 최대 낙폭이 15% 이상이고 현재 낙폭이 10% 이하이면 회복 단계 `70/30/0`
- 현재 낙폭이 10% 초과 15% 미만이면 직전 비중 유지
- QQQM이 200일선 미만이면 TQQQ를 한 버킷 낮춘다.
- VIX가 35 이상이면 TQQQ가 직전 비중보다 늘지 않게 제한한다. 첫 평가에는 실제
  계좌 비중을 기준으로 사용한다.
- 주문 직전 실제 비중의 편차가 5% 미만이면 리밸런싱하지 않는다.

VIX 보정은 기존 Java처럼 전략 상태 저장이 아니라 최종 목표 비중 결정에서 적용한다.

## 개별종목 신호 전략

개별종목 전략은 일봉, 롱 포지션, 한 전략당 한 종목만 지원한다. 종가에서 신호를
평가하고 다음 거래일 시가에 체결한다. 이미 참인 조건을 반복 매수하지 않고 거짓에서
참으로 바뀐 새 신호에서만 진입한다.

- 종가의 이동평균 상향 돌파 → 같은 이동평균 하향 돌파 시 청산
- 단기 이동평균의 장기 이동평균 상향 돌파 → 역교차 시 청산
- 이전 N일 고점 돌파 → 이전 N일 저점 이탈 시 청산
- RSI 과매도 기준 상향 회복 → 과매수 기준 도달 시 청산
- 보유 중에는 실제 평균 매입가 기준 손절·익절과 보유 후 최고 종가 기준 트레일링을 적용
- 보호 청산 뒤 고정 대기일은 두지 않으며 다음 새 매수 신호에서만 재진입

## 데이터 신뢰

- 실전 입력: KIS 또는 공식 기관이 문서화한 데이터
- 연구 입력: 무료 비공식 데이터 허용, 단 출처·가용 기간·경고 필수
- 재무 데이터: `released_at <= 평가 시각`인 관측값만 사용
- 현재 MVP는 사용자가 정한 고정 종목군만 지원하며 과거 시점별 스크리닝은 하지 않는다.
- 분봉에는 `observed_at`을 필수로 저장한다. 원시 틱과 호가창은 보존하지 않는다.
- Parquet 파일은 종목·연도·출처·콘텐츠 체크섬 단위의 불변 경로를 사용한다.
- CSV 직접 백테스트는 카탈로그 적재와 분리해 일회성 연구 입력으로 취급한다.
- 규칙이 이동평균을 필수 입력으로 사용하면 필요한 관측치가 쌓일 때까지 해당
  평가일을 워밍업으로 제외한다.
- QQQM의 선택 보호 입력인 MA·VIX가 없으면 보호를 조용히 생략하지 않고 결과에
  미적용 기간 경고를 남긴다.

## 계좌 안전 한도

모든 계좌는 정지 상태로 생성되며 다음 값을 빠짐없이 가져야 한다.

- 단일 매수 금액, 일일 매수 합계, 매수·매도를 합친 전체 주문 횟수
- 종목 최대 비중과 일일 손실

시장가·지정가, 분할 주문, 재가격, 자동 환전 같은 실행 프로필은 현재 주문 의도에
연결되지 않으므로 MVP에서 제거했다. 브로커 어댑터는 항상 비활성 상태다.

위험을 늘리는 매수의 한도 위반은 주문 의도를 차단하고 수동 확인 필요 상태로 표시한다.
보유 수량 이하의 보호·청산 매도는 매수 금액·일일 손실 한도와 무관하게 허용하되, 전체
주문 횟수를 넘으면 자동 계획하지 않고 수동 확인을 요구한다. 활성 계좌의 전략 교체는
먼저 계좌를 정지해야 하며, 새 전략의 관리 대상이 아닌 보유 종목이 있으면 전체 계획을
보류한다. 필수 가격이 하나라도 누락되면 부분 주문을 만들지 않는다. 접수 여부가 불명한
주문은 자동 재전송하지 않는다.

## 아직 운영에 적용하지 않는 항목

- KIS 실제 주문 어댑터
- 운영 서버 설치와 v2 프로세스 기동
- DNS 및 Cloudflare Access 정책 변경
- 기존 운영 DB·이력 이관과 Java 앱 종료
- 시점별 과거 스크리닝
- 지정가·분할·재가격·자동 환전을 포함한 고급 주문 실행

이 항목은 섀도 결과와 사용자 승인을 별도로 확인한 후 진행한다.
