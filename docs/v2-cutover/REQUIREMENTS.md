# v2 전환 요구사항

상태 표기:

- `충족`: 현재 근거가 인수 조건을 증명함
- `부분`: 기반은 있으나 인수 조건 전체를 증명하지 못함
- `미구현`: 개발 대상
- `증적 대기`: 기능은 있으나 사용자 화면 검증이 남음

진행 권한:

- `자동 진행 가능`: 읽기, 문서화, 기존 기능의 비변경 테스트처럼 주문·운영 전환이나 섀도 개발이 없는 작업
- `C0 범위 승인 이후 자동 진행 가능`: 사용자가 C0에서 승인한 전략·시점·
  스테이징 생성 범위 안에서만 자동 개발·테스트·데이터 생성을 진행함
- `사용자 승인 필수`: LIVE 주문, Java 중단, DNS·트래픽 전환, 롤백 확정 및 실제
  자격증명 사용

## 제품 목표

1. 기존 Java의 QQQM/QLD/TQQQ 전략을 끊지 않고 Python v2로 대체한다.
2. v2가 같은 입력에서 같은 상태와 목표 비중을 만드는지 자동 섀도로 증명한다.
3. 실주문 없이 화면에서 기능·안전 상태·차이를 검증하고 재현 가능한 증적을 남긴다.
4. 요구사항 → 기능 → 화면 → 테스트 → 배포 근거를 ID로 연결한다.

## 현재 단계의 비목표

- v2에서 실제 주문 전송
- Java 서비스·스케줄러·주문 경로 중단
- DNS 또는 공개 트래픽을 v2로 전환
- 운영 DB 이관, 기존 주문·체결 이력 재작성
- 전략 수치 자동 최적화 또는 QQQM/QLD/TQQQ 외 종목으로 기준선 변경
- 실제 KIS 자격증명을 이용한 브라우저 QA

이 항목들은 영구 제외가 아니라, 섀도 인수 후 별도 승인으로 여는 후속 단계다.

## 요구사항과 인수 조건

| ID | 요구사항 | 인수 조건 | 현재 | 권한 |
| --- | --- | --- | --- | --- |
| `V2-ACC-001` | 비공개 화면 접근 | 미인증 사용자는 Access로 이동하거나 거부되고, 허용 이메일만 UI·API에 접근한다. 원본 API는 loopback이며 무인증 `401`이다. | 증적 대기 | 브라우저 로그인 QA는 자동 진행 가능, 정책·DNS 변경은 사용자 승인 필수 |
| `V2-CUT-001` | Java 연속 운영 | 섀도 기간에 Java 코드·스케줄·DB·주문 경로를 변경하거나 중단하지 않는다. v2 장애가 Java 프로세스에 영향을 주지 않는다. | 부분 | Java 중단은 사용자 승인 필수 |
| `V2-CUT-002` | 단계 경계 공개 | 모든 화면과 문서가 `접근 배포`, `섀도`, `LIVE`를 별도 상태로 표시한다. 앞 단계 완료를 뒤 단계 완료로 표현하지 않는다. | 부분 | 자동 진행 가능 |
| `V2-STR-001` | 기준 전략 보존 | 종목군은 QQQM/QLD/TQQQ, 신호는 QQQM, 낙폭·회복·VIX·200MA·5% 허용 오차·매매 우선순위는 승인된 버전으로 고정된다. | 부분 | 규칙 변경은 사용자 승인 필수 |
| `V2-STR-002` | Java 결과 동등성 | 16:15 EOD 상태와 다음 거래일 09:45 리밸런싱 판단을 각각 같은 시점·입력으로 비교한다. 단계, 낙폭, 기준/최종 목표 비중, 보호 이벤트, 주문 방향·종목 순서가 정확히 일치한다. 수량 차이는 동일 가격·현금·반올림 입력으로 설명되고 승인 기준 안이어야 한다. | 부분 | C0 범위 승인 이후 자동 대조 가능, 예외 수용은 사용자 승인 필수 |
| `V2-AUT-001` | 자동 섀도 평가 | 미국 거래일 16:15 ET의 EOD 상태 계산과 다음 거래일 09:45 ET의 리밸런싱 의도 계산을 분리해 각각 한 번 실행한다. 휴장일을 건너뛰고 가능한 누락 일자를 멱등하게 보충하며 브로커 주문은 호출하지 않는다. | 미구현 | C0 범위 승인 이후 자동 진행 가능 |
| `V2-DAT-001` | 신뢰 가능한 입력 | 평가일, 출처, 관측·가용 시각, 공식 여부를 가진 QQQM/QLD/TQQQ·VIX·200MA·계좌 스냅샷을 사용한다. 필수 입력 누락·지연·혼합 기준일에는 평가를 차단한다. | 미구현 | C0 범위 승인 이후 읽기 전용 수집 자동 진행 가능, 실제 자격증명 등록은 사용자 승인 필수 |
| `V2-PER-001` | 멱등 저장과 추적 | 계좌·전략 버전·평가일·입력 체크섬별 결과를 한 번 저장하고, 재시도는 같은 결과를 돌려준다. 입력, 상태, 목표 비중, 주문 의도, 차이, 오류를 감사 가능하게 남긴다. | 부분 | C0 범위 승인 이후 자동 진행 가능 |
| `V2-SAF-001` | 구조적 주문 차단 | 섀도 환경은 `execution=false`, `broker=disabled`이며 앱 시작 검증과 DisabledBroker가 잘못된 설정·호출을 거부한다. 화면 테스트가 주문 제출 포트에 닿지 않는다. | 충족 | 설정 해제·LIVE 어댑터는 사용자 승인 필수 |
| `V2-OPS-001` | 운영 가시성 | 오늘의 스케줄, 데이터 완전성, 마지막 성공, Java 대조, 차단 이유, 안전 설정, 감사 이력을 한 화면에서 확인한다. | 부분 | C0 범위 승인 이후 섀도 가시성 개발·QA 자동 진행 가능 |
| `V2-UI-001` | 비개발자 화면 검증 | 각 화면은 무엇이 안전하고 무엇이 남았는지 쉬운 한국어로 보여 주며 모바일·데스크톱 핵심 흐름을 지원한다. `LIVE_APPROVED`가 주문 활성화로 오해되지 않는다. | 부분 | 기존 화면의 읽기 전용 QA는 자동 진행 가능, 섀도 화면 개발은 C0 범위 승인 이후 자동 진행 가능 |
| `V2-QA-001` | 재현 가능한 증적 | 배포 SHA, 시간, 환경, 안전 설정, 시나리오 입력·기대·실제 결과, 스크린샷, 실패 사유를 한 묶음으로 남기며 비밀값은 포함하지 않는다. | 부분 | 기존 화면의 비변경 안전 QA는 자동 진행 가능, 섀도 증적 개발·생성은 C0 범위 승인 이후 자동 진행 가능, 위험 시나리오는 사용자 승인 필수 |
| `V2-APR-001` | 위험 작업 수동 승인 | 실제 주문, Java 중단, DNS·트래픽 전환, 실제 자격증명 사용, 롤백 확정은 화면 확인 문구와 감사 기록을 포함한 사용자 승인 없이는 실행할 수 없다. | 부분 | 사용자 승인 필수 |
| `V2-REL-001` | 전환 게이트 | 권장 20개 연속 미국 거래일 동안 중대 불일치 0건, 스케줄 성공 100%, 데이터 차단 미해결 0건, 복구 훈련 성공 후에만 LIVE 후보가 된다. | 미구현 | LIVE 전환은 사용자 승인 필수 |
| `V2-RBK-001` | 결정 가능한 롤백 | v2 중지 → 미확정 주문 확인 → 데이터 보존 → Java 복귀 순서를 훈련하고, 목표 복구 시간·책임자·근거를 기록한다. | 부분 | 롤백 확정·Java 복귀는 사용자 승인 필수 |
| `V2-DOC-001` | 명세 우선 개발 | 새 기능은 요구사항 ID, 화면 영향, 실패 처리, 테스트와 증적 계획을 승인받은 뒤 구현한다. | 부분 | 문서 작성은 자동 진행 가능, 범위 승인은 사용자 승인 필수 |

## 기준 전략 계약 (`V2-STR-001`)

| 조건 | QQQM | QLD | TQQQ |
| --- | ---: | ---: | ---: |
| 정상 또는 낙폭 15% 미만(회복 히스테리시스 미활성) | 100 | 0 | 0 |
| 낙폭 15% 이상 25% 미만 | 60 | 30 | 10 |
| 낙폭 25% 이상 35% 미만 | 40 | 40 | 20 |
| 낙폭 35% 이상 45% 미만 | 30 | 30 | 40 |
| 낙폭 45% 이상 | 20 | 20 | 60 |
| 직전 상태의 최대 낙폭 15% 이상 경험 후 현재 낙폭 10% 이하 | 70 | 30 | 0 |

추가 계약:

- 현재 낙폭이 10% 초과 15% 미만일 때의 직전 기준 비중 유지는 **직전 상태의 ATH
  이후 최대 낙폭이 15% 이상이어서 회복 히스테리시스가 활성화된 경우에만**
  적용한다. 그 선행 이력이 없는 15% 미만 낙폭은 정상 비중 `100/0/0`을 적용한다.
- 16:15 ET EOD는 QQQM 종가로 상태와 기준 목표 비중만 저장한다.
- 다음 거래일 09:45 ET에 최신 EOD QQQM 종가가 조회한 200일선 아래면 TQQQ 노출을
  한 버킷 낮춘다.
- 같은 09:45 ET의 VIX가 35 이상이면 200MA까지 적용한 현재 조정 비중의 TQQQ가 직전 **기준 목표
  비중**의 TQQQ보다 늘어날 때 직전 기준 목표 **전체**를 유지한다. 직전 기준 목표가
  없는 첫 평가는 200MA 적용 후 현재 조정 비중 전체를 그대로 유지한다.
- 모든 관리 종목의 실제·목표 비중 차이가 5% 미만이면 주문 의도를 만들지 않는다.
  한 종목이라도 정확히 5% 이상이면 리밸런싱을 열고, 차이가 0이 아닌 모든 관리
  종목의 의도를 만든다.
- 매도 우선순위는 TQQQ → QLD → QQQM, 매수는 QQQM → QLD → TQQQ다.
- 이 계약은 현재 Python 기준선과 기존 문서에서 확인한 후보 기준이다. Java 운영
  결과와의 동등성은 `V2-STR-002` 증적 전까지 **검증 완료로 표현하지 않는다**.

## 품질 속성

- **결정성:** 같은 전략 버전과 입력 체크섬은 같은 결과를 낸다.
- **실패 폐쇄:** 입력이 불완전하거나 주문 상태가 불명확하면 진행하지 않는다.
- **시간 일관성:** 미래 공개 데이터나 서로 다른 평가일의 값을 섞지 않는다.
- **격리:** v2 장애·배포·DB가 Java 운영을 중단시키지 않는다.
- **설명 가능성:** 모든 차단과 목표 비중에는 사람이 이해할 이유가 있다.
- **비밀 보호:** 증적·로그·감사 화면에 키, 토큰, 계좌번호 전체를 남기지 않는다.
