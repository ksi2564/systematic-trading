# ADR-006: Python v2 독립 제품 계약

## 상태

승인 — 2026-08-19 사용자 결정

## 배경

PR #57에서 기존 Java 운영값을 읽기 전용으로 수집한 결과, C0-A와 다른 항목 및
검증·보존되지 않은 운영 의미가 다수 확인됐다. Java 서비스의 오류 알림도 계속되고 있어
Java 코드·설정·DB 결과를 Python v2의 정답으로 삼으면 기존 문제를 새 시스템에 그대로
옮길 위험이 있다.

사용자는 기존 Java를 따라가거나 검증·비교하지 않고, 이미 합의한 제품 기획을 바탕으로
Python 시스템을 독립적으로 새로 만들기로 결정했다. 이 결정은 PR #57의 C0-B 결과
재승인과 Java 동등성 비교를 C2 착수 조건으로 삼았던 이전 계획을 대체한다.

## 결정

1. Python v2의 정답은 사용자가 승인한 제품 규칙, 명시적인 입력·출력 계약, Python이
   소유한 테스트와 불변조건이다.
2. Java 코드·설정·DB 상태·실행 결과·golden fixture·허용 오차를 Python의 초기값,
   oracle, 회귀 기준 또는 릴리스 통과 조건으로 사용하지 않는다.
3. C0-B 증적 커밋 `2638efbf4648e4da5b9dc0f8f00e80403ae2ddca`는 당시 운영 상태의
   역사 기록으로만 보존한다. 내용은 수정하거나 Python 검증 근거로 승격하지 않는다.
4. Java 운영 서비스의 중단·삭제·주문 소유권 변경은 이 결정에 포함하지 않는다. 실제
   전환 전까지 Python은 Java에 의존하지 않으며 Java를 변경하지도 않는다.
5. 기능은 한 번에 하나의 도메인 규칙 또는 하나의 외부 포트만 포함하는 작은 단위로
   개발한다. 각 단위는 입력, 출력, 제외 범위와 테스트를 함께 제시한다.
6. 결과를 바꾸는 제품 선택이 명세에 없으면 구현자가 추정하지 않고 사용자에게 확인한다.

## 첫 번째 개발 단위

첫 단위는 `PYTHON_QQQM_EOD_V1` 상태 전이이다.

- 입력: Python이 만든 직전 EOD 상태와 해당 시장일의 확정 QQQM 종가
- 출력: ATH, 현재·최대 낙폭, 단계, 낙폭 구간, QQQM/QLD/TQQQ 기준 비중
- 제외: 최초 상태 생성, VIX, MA200, 계좌, 호가, 수량, 스케줄러, DB, 네트워크,
  API·화면, 주문 제출
- 안전 동작: 직전 Python 상태가 없으면 Java 상태로 채우지 않고 초기 상태 생성 정책의
  사용자 확인을 요구한다.
- 입력 경계: 이 순수 계산기는 공급자·시장일·확정 여부를 조회하지 않는다. 호출자가
  별도 입력 계약으로 검증한 종가만 전달해야 한다.
- 정밀도: 단계와 낙폭 구간은 화면 반올림 전의 소수점 24자리 canonical Decimal 값으로
  판단한다. 네 자리 반올림은 사람에게 보여 주는 설명에만 사용한다.
- checksum: 계약 버전, 시장일, 가격, 낙폭, 단계와 기준 비중만 포함하며 사람용 설명
  문구는 포함하지 않는다. 같은 숫자의 불필요한 뒤쪽 0은 제거해 정규화한다.

## 결과

- Python 계산은 Java 장애나 Java 결과 부재와 무관하게 검증할 수 있다.
- 기존 통합 평가기의 EOD·다음 날 판단 혼합은 작은 단계로 분리해 교체한다.
- 최초 상태를 어떤 시장 데이터 범위에서 만들지는 다음 개발 단위 전에 별도로 확정한다.
- PR #57은 Python 기능의 기준으로 사용하지 않고 C0-B 감사 이력을 보존하는 참조로
  남긴다. PR의 병합·종료 처분은 별도로 판단한다.
