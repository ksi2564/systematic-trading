## 직접 내려받은 증적 검증

CI 성공 표시만 확인하지 않고 위 네 ZIP을 내려받아 다음을 별도로 검사했다.

### 기획 보드 artifact

- 내려받은 두 ZIP의 SHA-256이 GitHub archive digest와 각각 일치한다.
- push manifest의 `sourceSha`는 source 정본, PR manifest의 `sourceSha`는 test-merge와
  일치하며 두 manifest 모두 `gitClean: true`다.
- 두 lane의 `sourceTreeSha256`은 동일하다.
- manifest가 지정한 소스 5개의 실제 파일 SHA-256과 tree digest를 다시 계산해
  일치함을 확인했다.
- 320px PNG는 검토 완료 1장, 미래 화면 5장, 단일 추적표 1장으로 정확히 7장이다.
- 각 manifest의 PNG SHA-256이 ZIP 안 실제 PNG와 모두 일치한다.
- 두 CI lane 모두 PNG 폭은 320px이며 최대 높이는 9,497px, 추적표는 9,113px로
  10,000px 상한 안이다.
- JUnit은 두 lane 모두 `2 tests / 0 failures / 0 errors`다.

### 로컬 mock UI artifact

- 내려받은 두 ZIP의 SHA-256이 GitHub archive digest와 각각 일치한다.

## 실행하지 않았고 남아 있는 항목

- 실제 주문, KIS 자격증명·계좌 식별자·비밀번호·OTP 입력 또는 저장
- 후보 배포, staging/운영 변경, 릴리스 링크 변경, 서비스 재시작
- Java 프로세스·전략·스케줄·DB 확인·변경·중지
- DNS·Tunnel·Cloudflare Access 정책 변경
- 인증된 배포 화면 `QA-ACC-002`, 상태 변경 QA, 공유 환경 복구 훈련
- 자동 shadow runner, 공식 운영 데이터 adapter, Java 운영 결과 comparator, 주문 제출 연동

현재 운영 Java 자동매매 프로세스는 이번 로컬 검증 대상이 아니어서 직접 확인하지
않았다. Java/Python golden parity와 scheduler 계약은 CI가 통과했지만, 이는 현재 운영
Java의 실제 설정·최근 실행·주문 모드를 증명하지 않는다. 그 값은 C0-A 뒤 별도 허가를
받아 읽기 전용 C0-B로 수집하고 사용자가 다시 승인해야 한다.

GitHub Actions의 Node.js 20 강제 전환과 `setup-java@v4` 지원 종료 예고는 비실패
경고로 남아 있다.
