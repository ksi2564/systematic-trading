# v2 화면 기획과 검토 흐름

비개발자용 [전환 검토 보드](review-board/index.html)의 `화면 미리보기`에서
`S-01 오늘의 운영`, `S-04 자동 병행 비교`, `S-08 검증 증적`, `S-10 운영값 재확인`,
`S-09 전환 센터`를 더미
데이터로 먼저 볼 수 있다. 버튼은 비활성이며 선택·주문·승인 값은 저장하거나 전송하지
않는다. 이 미리보기는 개발 승인이나 배포 완료 증적이 아니다.

## 1. 화면이 답해야 하는 세 가지

화면을 처음 본 사람이 10초 안에 아래를 알 수 있어야 한다.

1. **안전한가요?** 실주문이 꺼져 있는지 가장 먼저 보인다.
2. **오늘 잘 돌았나요?** 데이터 수집, Python 판단, Java 대조 상태가 한 흐름으로 보인다.
3. **제가 할 일이 있나요?** 차이·누락·승인 대기를 쉬운 문장으로 안내한다.

현재 화면은 전략 연구·계좌·안전 제어를 제공한다. 자동 섀도 현황, Java 비교, QA 증적
다운로드 화면은 개발 대상이다.

## 2. 토스처럼 편하게 읽는 원칙

- 한 화면에는 가장 중요한 결정 하나만 둔다.
- 첫 줄은 상태, 둘째 줄은 이유, 셋째 줄은 다음 행동으로 쓴다.
- `LIVE_APPROVED`, `INPUT_BLOCKED` 같은 내부 코드는 보조 정보로만 노출한다.
- 성공은 초록색만으로 표현하지 않고 아이콘과 문장을 함께 쓴다.
- 위험 버튼은 일상 버튼과 떨어뜨리고 결과를 확인 문구에 구체적으로 적는다.
- 숫자는 비교 기준과 단위를 붙인다. 예: `목표 비중 10% · 기존과 같음`.
- 상세 로그는 접어 두고, 비개발자가 이해할 요약을 먼저 보여 준다.
- 모바일에서도 안전 배너, 오늘 상태, 내가 할 일 순서를 유지한다.
- 기획 결정은 한 번에 하나만 펼치고, 선택만으로 자동 이동하지 않는다. 필수 메모까지
  완료해야 명시적인 `다음 미응답 보기`를 누를 수 있다.

## 4. 화면별 명세

### S-00. 비공개 접근

**현재 기반:** Cloudflare Tunnel, Access 이메일 허용 목록, 원본 API 인증 경계
**현재 증적:** `QA-ACC-001`에서 미인증 UI/API의 Access 이동 확인
**남은 완료 조건:** 허용 이메일 로그인·동일 출처 UI/API와 비허용 계정 거부 증적

- 미로그인: Cloudflare 로그인으로 이동한다.
- 비허용 이메일: 화면과 API 모두 거부한다.
- 허용 이메일: 같은 출처의 UI와 API가 열린다.
- 화면에는 이메일 허용 목록이나 내부 IP를 노출하지 않는다.

### S-01. 오늘의 운영

상단 고정 카드:

```text
실주문은 꺼져 있어요
Python v2는 결과만 계산하고 주문을 보내지 않아요.
[execution false] [broker disabled]
```

이 안전 카드는 동일 출처 API가 `execution_enabled=false`,
`broker_adapter=disabled`를 확인했을 때만 보여 준다. 초기 로딩, 401/500, 타임아웃,
타입 불일치, true/disabled 조합에서는 “안전 상태 확인 불가” 또는 불안전 상태를
표시하고 생성·승격·재개·정지 해제처럼 위험을 키우는 조작을 잠근다. 위험 감소용
`v2 신규 제출 차단`은 잠금 밖에 두어 계속 누를 수 있게 하며, API에도 닿지 못하면
차단 성공으로 오인하지 않도록 실패를 명시한다.

그 아래에는 C0-B에서 실제 동작을 확인한 기존 시스템의 두 실행 시점을 합치지 않고 보여 준다.

| 실행·카드 | 기본 문구 | 보조 정보 |
| --- | --- | --- |
| 16:15 EOD 상태 | 오늘 기준 비중을 계산했어요 | 시장일, phase, QQQM/QLD/TQQQ 기준 비중 |
| 16:15 Java 비교 | 기존 EOD 상태와 비교했어요 | 같음 또는 승인된 데이터 개선 차이, 비교 시각 |
| 다음 거래일 09:45 의도 | 보호 규칙과 5% 판단을 마쳤어요 | 계좌·호가·VIX·200MA 시각, 최종 비중, 의도 수 |
| 09:45 Java 비교 | 기존 리밸런싱 판단과 비교했어요 | 방향·종목 순서·수량·위험 규칙 영향 |

문제가 있으면 성공 카드 대신 한 개의 “확인 필요” 카드로 합치고, 가장 먼저 해결할
원인을 보여 준다.

### S-02. 전략 기준선

기존 전략 빌더를 유지하되 QQQM 기준선에는 “검증 상태” 요약을 추가한다.

- 종목: QQQM / QLD / TQQQ
- 낙폭 구간과 비중을 표보다 막대 카드로 먼저 표시
- 회복, VIX 35, QQQM 200MA, 5% 허용 오차를 쉬운 문장으로 표시
- 전략 버전·checksum·승인자는 상세에서 확인
- C0에서는 시험 전략의 종류·건수·정리 기준만 확정한다. 공유 시험 서버 생성은
  대상·영향·정리 방법을 다시 보여 주고 실행 직전 사용자 승인을 받는다.
- 현재의 “Java 동작을 그대로 재현” 문구는 동등성 증적 전까지
  “기존 규칙을 기준으로 만든 Python 후보”로 바꾼다.
- `LIVE_APPROVED` 버튼은 “실전 후보로 표시”라고 쓰고 “주문은 켜지지 않아요”를
  확인창에 함께 표시한다.

### S-03. 연구·검증

현재 단일 평가, CSV 백테스트, 롤링 검증을 유지한다.

결과 순서:

1. 현재 단계와 낙폭
2. 목표 비중 막대
3. 보호 규칙 적용 여부
4. 입력 데이터와 경고
5. 상세 이벤트

대표 화면 QA 예시:

| 입력 | 기대 요약 |
| --- | --- |
| QQQM 85, 과거 종가 90·100·95, VIX 20, 200MA 90 | 낙폭 15%, `DRAWDOWN`; 기준 60/30/10에서 200MA 방어 후 최종 100/0/0 |

CSV를 선택했을 뿐이면 “서버 데이터로 저장되지 않았어요”를 유지한다. 백테스트 결과가
좋아도 자동 승격하지 않는다.

### S-04. 자동 섀도

**신규 화면.** 최근 20개 거래일을 날짜별로 묶고, 각 날짜 안에서 16:15 EOD와 다음
거래일 09:45 리밸런싱을 별도 행으로 표시한다.

| 표시 | 내용 |
| --- | --- |
| 상태 | 완료, 차이 발견, 입력 대기, 실패, 휴장 |
| 실행 | `EOD_STATE 16:15 ET` 또는 `REBALANCE_INTENT 09:45 ET` |
| Python | EOD는 phase·기준 비중, 09:45는 최종 비중·주문 의도 수 |
| Java | 동일 필드 또는 대조 불가 |
| 비교 가능성 | 알고리즘 `COMPARABLE`; 실제 결과는 같음, `APPROVED_DATA_IMPROVEMENT`, 또는 차단 사유 |
| 데이터 개선 차이 | 데이터 contract/version, 확정 원가격 종가·완료 거래일 MA200 관련 입력 필드, Java/Python delta |
| 영향·확인 | 방향·수량·위험 규칙 영향과 사용자 확인 대기/완료 상태 |
| 차이 | 필드, 기존 값, 새 값, 영향 |
| 근거 | `eod_market_date`, `rebalance_market_date`, 입력 체크섬, 출처, 실행 시각, 배포 SHA |

차이 상세는 “무엇이 달랐나요 → 왜 중요하나요 → 다음에 무엇을 하나요” 순서로 쓴다.
`다시 계산`은 같은 입력에 멱등해야 하며, 새 입력이면 별도 시도로 남는다고 안내한다.
목록은 `GET /api/v2/shadow/runs`, 상세는
`GET /api/v2/shadow/runs/{run_id}`의 마스킹된 응답만 사용한다.

### S-05. 계좌·위험

현재 계좌 생성, 위험 한도, 전략 할당, 정지·재개 화면을 유지한다.

- 신규 계좌는 항상 `정지됨`으로 보인다.
- 테스트 계좌에는 `스테이징 테스트` 표식을 붙인다.
- C0에서는 시험 계좌의 종류·건수·정리 기준만 확정한다. 공유 시험 서버 생성은
  대상·영향·정리 방법을 다시 보여 주고 실행 직전 사용자 승인을 받는다.
- 자격증명 영역은 기본 접힘이며 실제 값은 다시 표시하지 않는다.
- `확인 후 재개`는 자동 판단 상태만 바꿀 수 있음을 알리고, 실주문 차단 상태를 함께
  보여 준다.
- 실제 KIS 자격증명 저장·계좌 재개는 자동 QA에서 제외한다.

### S-06. 데이터

현재 카탈로그에 아래를 추가한다.

- 평가 가능/불가 상태
- 공식/연구 출처
- 기준일, 관측 시각, 가용 시각
- 누락된 종목·필드
- 섀도 실행에서 실제 사용된 체크섬 링크

카피 예시: “QLD 종가가 아직 확정되지 않아 오늘 계산을 멈췄어요.”

### S-07. 안전·감사

현재 전체 긴급 정지, 구조적 안전장치, 감사 기록을 유지한다.

- 현재 실행 플래그와 브로커 어댑터를 상단에 크게 표시
- 안전 설정 불일치·API 불가 시 초록 성공 표시를 제거하고 `v2 신규 제출 차단`만 잠금
  밖에 유지한다. 이 버튼은 Java를 멈추거나 브로커 주문을 취소하지 않는다.
- 전체 정지는 스테이징 섀도 판단을 멈추며 Java를 멈추지 않는다고 명시
- 정지 해제 전 영향 범위를 확인창에 표시
- 감사 행을 누르면 변경 전/후, 행위자, 이유, 배포 SHA를 보여 준다.

Java의 저장소 기본 설정은 `PAPER`·execution disabled지만, 화면은 원격 Java 운영
모드를 확인하지 못한 상태에서 `PAPER`라고 단정해서는 안 된다. 별도 런타임 조회가
없으면 “기존 시스템 모드 확인 필요”로 표시한다.

### S-08. QA 증적

**신규 화면.** 배포별 시나리오 진행률과 증적을 묶는다.

현재 인증 배포 QA 후보가 만드는 성공 bundle의 고정 계약은 다음과 같다. 후보 배포는
사용자 승인 뒤에만 실행하고, 배포된 뒤의 GET-only QA만 자동 진행한다.

- SPA 전에 exact `/health`와 후보 전용 read-only snapshot만 backend로 조회한다.
- 화면의 5개 논리 API GET은 고정 snapshot으로 브라우저에서 응답하며 backend 전송은
  0건이어야 한다.
- 오늘의 운영·전략 빌더·연구·검증·계좌·위험·데이터·안전·감사 6개 화면을
  1440×1000과 360×800에서 각각 캡처한다.
- 화면별 등록 민감 영역의 정확한 집합·유일성·표시 상태·비영 크기와 미등록 민감 marker
  0개를 캡처 전에 확인한다.
- opaque mask PNG 12개, viewport별 정제 관찰 JSON 2개, `manifest.json` 1개, 정확히
  15파일만 남긴다. reporter와 독립 verifier가 순서·파일명·권한·SHA-256·내용을
  모두 확인해야 성공이다.

아래 항목은 미래 S-08 화면에 보여 줄 release 기록 계약이다. “Markdown 요약”은 사용자가
요청할 때 화면/API에서 생성하는 출력이며 `QA-ACC-002` 보존 bundle의 16번째 파일이 아니다.

- 배포 SHA·환경·브라우저·실행 시각
- 통과/실패/수동 보류/차단/해당 artifact 범위 외 개수
- 시나리오별 기대값과 실제값
- 마스킹된 스크린샷·API 안전 상태
- 다운로드 가능한 `manifest.json`과 Markdown 요약
- 생성·변경·삭제된 전략, 계좌, 연구 run, 섀도 구독, 제어·감사 대상의 ID,
  변경 전/후, 보존 기한과 정리 결과

비밀값, OTP, Access 토큰, 계좌번호 전체는 캡처 전에 가린다.

### S-10. 운영값 재확인

**C0-B 사용자 재승인 화면.** C0-A가 끝나도 바로 생성하지 않는다. 12개 대상,
`GitHub Actions PROD SSH → 운영 호스트 shell 조회·DB SELECT` 접근 방법, 읽기 전용 권한,
정제 의무, `docs/v2-cutover/evidence/c0b/` 저장 위치, 원문 미저장, Git 이력 보존을
사용자가 별도로 승인한 뒤 수집한 12개 운영 항목을 다음 순서로 보여 준다.

1. 마스킹된 현재 값의 쉬운 요약
2. C0-A에서 승인한 값과 `같음` 또는 `다름`
3. 읽기 전용 수집 시각과 수집 방식
4. 원천·차이 파일의 SHA-256
5. 차이가 미치는 전략·자동 실행·주문 안전 영향

계좌번호·전자우편·비밀번호·token·cookie·API/private key·원문 환경변수는 표시하거나
저장소 증적에 넣지 않는다. 각 항목의 정제된 요약과 facts, 차이 문장은
`C0_DECISIONS.md`의 item·diff artifact 계약을 따른다. 12개 중 하나라도 누락되거나
checksum·문서 SHA·시간 순서가 맞지 않으면 최종 재승인 조작을 잠그고 이유를 먼저
표시한다. C0-B 화면 자체는 주문·Java 중단·배포·접속 경로 변경 권한을 갖지 않는다.

### S-09. 전환 센터

**미래 수동 전용 화면.** 개발·QA가 자동으로 누르지 않는다.

단계는 순서대로만 열린다.

1. C0-A 제품 규칙 승인
2. C0-B ① 운영값 읽기 별도 승인
3. C0-B ② 정제된 운영값·차이 결과 재승인
4. C2 주문 없는 자동 병행 개발·격리 QA
5. C2 후보 SHA 배포 별도 승인
6. C3 대상·기간·영향 실행 별도 승인
7. 알고리즘·운영 결과·production 준비의 세 20거래일 레인 통과
8. C4-A LIVE 후보 개발·실증권사 연결 없는 simulator 격리 인수
9. C4-B 주문 없는 복구 훈련 통과
10. C5 제출 차단 후보 배포 별도 승인
11. C5-A 사용자 별도 승인 뒤 v2 단건 제출·대조
12. C5-B 범위·기간 승인·활성화 뒤 승인 범위에서 시스템 자동운용 5주기·대조
13. C6 전체 전환과 연속 미국 거래일 20일 안정화
14. C7 Java 퇴역 별도 승인

C2 후보 배포, C3 실행, C5 제출 차단 후보 배포, C5-A 실제 단건 제출은 각각 별도
카드·승인·증적 상태로 표시한다. C5-A와 C5-B도 합치지 않으며, C5-A 단건 성공만으로
자동운용 인수를 통과했다고 표시하지 않는다. C5-B는 승인 최대 종료일과 남은 기간을
함께 보여 준다. C6도
범위 확대와 20거래일 안정화를 별도 진행률로 표시한다.

C5-A 대조가 끝난 같은 운영 세션에서는 미확정 주문 0건과 함께 `C5-B 진입` 또는
`Java 주문 소유권 복원` 선택을 반드시 보여 준다. 이 선택은 14개 상위 단계 카드 사이의
종료 하위 게이트이며, 사용자가 선택할 수 없는 상태라면 C5-A 시작 자체를 잠근다.

다음은 각각 별도 확인과 감사 이벤트가 필요하다.

- LIVE 주문 활성화
- Java 자동 주문 중단
- DNS·트래픽 경로 전환
- 실패 후 롤백 확정

## 5. 상태 문구 사전

| 내부 상태 | 화면 제목 | 설명 |
| --- | --- | --- |
| `COMPLETED` | 오늘 계산을 마쳤어요 | Python 결과와 기존 결과가 같아요. |
| `DIFF_FOUND` | 결과가 달라 확인이 필요해요 | 주문은 보내지 않았고 차이를 저장했어요. |

| `LEGACY_UNAVAILABLE` | 기존 결과를 아직 비교하지 못했어요 | Python 결과만으로 전환 여부를 판단하지 않아요. |

| `LIVE_APPROVED` | 실전 후보로 표시했어요 | 실주문은 여전히 꺼져 있어요. |

## 6. 반응형·접근성 인수 조건

- 360px 너비에서 가로 스크롤 없이 안전 상태와 오늘 결과를 읽을 수 있다.
- 모든 조작은 키보드로 가능하고 포커스가 보인다.
- 상태는 색 외에 아이콘·텍스트를 함께 쓴다.
- 확인창은 대상, 영향, 되돌리는 방법을 포함한다.
- 날짜는 화면에 KST와 시장 기준일을 구분해 표시한다.
- 오류는 재시도만 요구하지 않고 원인과 안전 상태를 함께 설명한다.
