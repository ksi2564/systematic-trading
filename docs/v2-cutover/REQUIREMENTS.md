# v2 전환 요구사항

상태 표기:

- `충족`: 현재 근거가 인수 조건을 증명함
- `부분`: 기반은 있으나 인수 조건 전체를 증명하지 못함
- `미구현`: 개발 대상
- `증적 대기`: 기능은 있으나 사용자 화면 검증이 남음

진행 권한:

- `자동 진행 가능`: 읽기, 문서화, 기존 기능의 비변경 테스트처럼 주문·운영 전환이나 섀도 개발이 없는 작업
- `C0-B 결과 재승인 뒤 자동 진행 가능`: D-01~D-10의 C0-A 확정만으로 운영값
  접근이나 C2 개발을 허가하지 않음. 읽기 전용 대상·접근 방식·정제 및 저장 범위를
  사용자가 별도로 승인한 뒤 C0-B 운영 snapshot·diff를 수집하고, 사용자가 최종
  checksum과 차이를 다시 승인한 전략·시점 기준으로 개발과 로컬·mock·일회용 격리
  테스트를 진행함. D-07 선택은 공유 시험 서버 자원 생성·변경의 실행 승인이 아님
- C0-B 수집 승인에는 12개 대상뿐 아니라 `GitHub Actions PROD SSH → 운영 호스트
  shell 조회·DB SELECT`라는 접근 방법, 읽기 전용 권한, 정제 의무,
  `docs/v2-cutover/evidence/c0b/` 저장 위치, 원문 미저장, Git 이력 보존을 함께 기록함
- `사용자 승인 필수`: 후보 배포, 공유 시험 서버 자원 생성·상태 변경·스케줄 시작,
  LIVE 주문, Java 중단, DNS·트래픽 전환, 공유 staging/운영 롤백 확정 및 실제 자격증명 사용.
  실행 직전에 대상·영향·정리·복구 방법을 다시 보여 줌

## 제품 목표

1. 기존 Java의 QQQM/QLD/TQQQ 전략을 끊지 않고 Python v2로 대체한다.
2. v2가 같은 입력에서 같은 상태와 목표 비중을 만드는지 자동 섀도로 증명한다.
3. 실주문 없이 화면에서 기능·안전 상태·차이를 검증하고 재현 가능한 증적을 남긴다.
4. 요구사항 → 기능 → 화면 → 테스트 → 배포 근거를 ID로 연결한다.

## 현재 단계의 비목표

- v2에서 실제 주문 전송
- Java 서비스·스케줄러·주문 경로 중단
- DNS 또는 공개 트래픽을 v2로 전환
- 운영 DB 이관, 기존 주문·체결 이력 재작성
- 전략 수치 자동 최적화 또는 QQQM/QLD/TQQQ 외 종목으로 기준선 변경
- 실제 KIS 자격증명을 이용한 브라우저 QA

이 항목들은 영구 제외가 아니라, 섀도 인수 후 별도 승인으로 여는 후속 단계다.

## 기준 전략 계약 (`V2-STR-001`)

| 조건 | QQQM | QLD | TQQQ |
| --- | ---: | ---: | ---: |
| 정상 또는 낙폭 15% 미만(회복 히스테리시스 미활성) | 100 | 0 | 0 |
| 낙폭 15% 이상 25% 미만 | 60 | 30 | 10 |
| 낙폭 25% 이상 35% 미만 | 40 | 40 | 20 |
| 낙폭 35% 이상 45% 미만 | 30 | 30 | 40 |
| 낙폭 45% 이상 | 20 | 20 | 60 |
| 직전 상태의 최대 낙폭 15% 이상 경험 후 현재 낙폭 10% 이하 | 70 | 30 | 0 |

추가 계약:

- 현재 낙폭이 10% 초과 15% 미만일 때의 직전 기준 비중 유지는 **직전 상태의 ATH
  이후 최대 낙폭이 15% 이상이어서 회복 히스테리시스가 활성화된 경우에만**
  적용한다. 그 선행 이력이 없는 15% 미만 낙폭은 정상 비중 `100/0/0`을 적용한다.
- 16:15 ET EOD는 해당 미국 거래일의 확정 원가격 종가로 상태와 기준 목표 비중만
  저장한다. 공급자·공식 확정 시각·corporate action 처리의 실제 계약은 C0-B 결과
  재승인 전까지 확정된 구현값으로 표현하지 않는다.
- 다음 거래일 09:45 ET에 최신 EOD QQQM 기준 가격이 조회한 200일선 아래면 TQQQ 노출을
  한 버킷 낮춘다.
- 같은 09:45 ET의 VIX가 35 이상이면 200MA까지 적용한 현재 조정 비중의 TQQQ가 직전 **기준 목표
  비중**의 TQQQ보다 늘어날 때 직전 기준 목표 **전체**를 유지한다. 직전 기준 목표가
  없는 첫 평가는 200MA 적용 후 현재 조정 비중 전체를 그대로 유지한다.
- 모든 관리 종목의 실제·목표 비중 차이가 5% 미만이면 주문 의도를 만들지 않는다.
  한 종목이라도 정확히 5% 이상이면 리밸런싱을 열고, 차이가 0이 아닌 모든 관리
  종목의 의도를 만든다.
- 매도 우선순위는 TQQQ → QLD → QQQM, 매수는 QQQM → QLD → TQQQ다.
- 이 계약은 현재 Python 기준선과 기존 문서에서 확인한 후보 기준이다. Java 운영
  결과와의 동등성은 `V2-STR-002` 증적 전까지 **검증 완료로 표현하지 않는다**.

### C0에서 확정할 숨은 전략·데이터 의미

현재 Java 후보 코드에는 화면의 전략 숫자만으로 알 수 없는 계약이 있다.

- 16:15 EOD 입력은 KIS 응답의 `base`/`prevClosePrice`이며 같은 시장일의 확정 종가인지
  실제 응답 기준일 확인이 필요하다.
- 초기 ATH는 `365`라는 상수와 달리 Yahoo `range=1y`의 실제 가용 종가 행을 사용한다.
- 09:45 VIX는 현재값이고 MA200은 Yahoo 일봉의 최근 비어 있지 않은 200개 값이지만,
  진행 중 세션·조정주가 포함 여부가 명시돼 있지 않다.
- 현재 Java 후보에서 VIX의 “직전 기준 목표”는 최신 EOD 상태보다 바로 전 EOD 상태를
  조회한 값이다.
- 지표 누락 시 Java 후보는 보호를 생략하지만 안전한 v2는 계산을 차단하는 방향이다.

이 항목은 [`C0_DECISIONS.md`](C0_DECISIONS.md)의 D-01~D-06에서 승인하기 전까지 제품
계약으로 확정하지 않는다. 정상 입력의 알고리즘 차이, 입력 차이, 승인된 안전 차이,
Java 결과 부재를 서로 다른 판정으로 보존한다.

## 품질 속성

- **결정성:** 같은 전략 버전과 입력 체크섬은 같은 결과를 낸다.
- **실패 폐쇄:** 입력이 불완전하거나 주문 상태가 불명확하면 진행하지 않는다.
- **시간 일관성:** 미래 공개 데이터나 서로 다른 평가일의 값을 섞지 않는다.
- **격리:** v2 장애·배포·DB가 Java 운영을 중단시키지 않는다.
- **설명 가능성:** 모든 차단과 목표 비중에는 사람이 이해할 이유가 있다.
- **비밀 보호:** 증적·로그·감사 화면에 키, 토큰, 계좌번호 전체를 남기지 않는다.
